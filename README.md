# parser-ecom

Локальная веб-версия собирает свежие новости из RSS. GigaChat 2 Lite (`GigaChat-2`) за один текстовый запрос без режима рассуждений определяет тему, пишет выжимку и выделяет ключевые слова. Elasticsearch ищет дубликаты по этим словам через BM25. PostgreSQL хранит исходники, результаты обработки и готовые новости для веб-ленты.

## Запуск веб-версии

1. Запустите Docker и подготовьте `.env` по образцу `.env.example`. Для классификации заполните `GIGACHAT_CLIENT_ID`, `GIGACHAT_CLIENT_SECRET` и при необходимости `GIGACHAT_SCOPE`.
2. Выполните команды из каталога проекта.

   ```sh
   docker compose up -d --build
   docker compose ps -a
   ```

3. Откройте [ленту](http://127.0.0.1:8000/) и нажмите «Обновить». Веб-страница показывает ход сбора и число исходников, которые ждут обработки. Первый сбор также запускается автоматически при старте воркера.

```sh
docker compose logs -f parser ai cleanup
docker compose exec parser python bot.py
docker compose down
```

Веб-адрес по умолчанию доступен с локального компьютера. Для размещения на сервере настройте HTTPS и авторизацию для ручного запуска через обратный прокси. Пароли из образца предназначены для локального теста. PostgreSQL и Elasticsearch работают во внутренней сети Compose. Локальный оверлей `docker-compose.local.yml` дополнительно открывает Elasticsearch только на интерфейсе обратной петли.

Если Docker Hub недоступен, запустите сборку через зеркало:

```sh
APP_PYTHON_IMAGE=mirror.gcr.io/library/python:3.14-slim \
POSTGRES_IMAGE=mirror.gcr.io/library/postgres:17 docker compose up -d --build
```

## API

- `GET /api/news?limit=20&offset=0` возвращает уникальные, прошедшие обработку новости от новых к старым.
- `GET /api/news/{id}` возвращает одну новость.
- `POST /api/refresh` ставит сбор в очередь и отвечает кодом `202`.
- `GET /api/refresh` показывает состояние сбора, очереди AI и режим Telegram.
- `GET /docs` открывает документацию FastAPI.

Telegram работает в режиме заглушки. Токен не нужен. Сообщения не отправляются, флаг `is_posted` остаётся `false`.

## Хранение и дедупликация

Парсер запускает сбор каждые 30 минут по умолчанию. Интервал отсчитывается от начала последнего сбора, включая ручной. Если предыдущий сбор ещё идёт, новый проход ждёт его завершения. И кнопка «Обновить», и автоматический сбор принимают новости за последние 24 часа по дате публикации. Записи без даты публикации и с датой в будущем пропускаются. На загрузку каждой ленты или статьи отводится до 5 секунд. При сбое парсер переходит к следующей записи или источнику.

Лента новостей «Известий» читается через системный `curl`, который входит в Docker-образ. После HTTP 429 следующий запрос к этой ленте или другому источнику откладывается до `Retry-After`, а при отсутствии заголовка — на 30 минут. Если текст статьи ТАСС или «Известий» недоступен, парсер может сохранить содержательный анонс из RSS. Такие новости отмечаются в ленте пометкой «По анонсу RSS».

Источники и словарь e-commerce заданы в `config.py`. Совпадения в заголовке и тексте подсказывают GigaChat тематику. Статьи без совпадений тоже проходят классификацию. AI забирает исходники из PostgreSQL и повторяет обработку после временных ошибок. После трёх некорректных ответов GigaChat исходник остаётся с `checked=false` и попадает в счётчик «Требуют проверки».

Elasticsearch ищет совпадения по фразам из результата GigaChat. Настройки `NEWS_DUPLICATE_SCORE` и `NEWS_DUPLICATE_MIN_MATCHES` задают стартовые критерии. Для оценки качества их нужно проверить на примерах разных публикаций об одном событии и разных событий одной компании.

Уникальная новость становится доступна в веб-ленте после подтверждённой индексации. PostgreSQL хранит отдельные задания индексации и удаления. После сбоя повтор откладывается только для задания с ошибкой, а новая статья остаётся с `checked=false` до успешной проверки и индексации. Очистка запускается каждый час. Уникальная новость хранится 30 дней от создания, свободный исходник — 30 дней от получения. Исходник, на который ссылается уникальная новость, хранится как минимум до её удаления.

Новая веб-лента заполняется из PostgreSQL по мере сбора и обработки. Старые документы Elasticsearch из прежней версии автоматически в неё не импортируются. Поиск использует отдельный индекс `ecom-keywords-v1`.
